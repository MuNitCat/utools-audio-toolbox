# 主题变量失效：深色下边框与背景全透明

| 项 | 值 |
|---|---|
| 日期 | 2026-11-18 |
| 影响版本 | UI 三栏改版后的中间构建（`src/styles/global.css` 使用 `light-dark()` 的版本），**未发布过** |
| 严重级别 | 高（界面不可用：控件无边界、选中态不可辨） |
| 状态 | 已修复 |
| 涉及文件 | `src/styles/global.css`、`src/core/store.js`、`index.html`、`AGENTS.md` |

## 现象

在 uTools 里打开插件（系统深色）：

- 所有边框消失：面板分隔线、卡片描边、拖放区虚线、标题栏底边，全部看不见
- 所有背景消失：选项按钮、输入框、导航选中项、开关轨道，与窗口底色完全同色
- 「同编码直转」那个开关只剩一个**白色圆点**飘着，没有轨道
- 切到「白天」主题后画面几乎没变化，仍然是深色一片

## 影响范围

- 深色、浅色**两种模式**都坏，不是只坏深色
- 唯一还正常显示的是**硬编码颜色**的元素（开关圆点 `#fff`、强调色按钮文字）
- 功能逻辑不受影响（拖文件、转码、MCP 都正常），纯视觉

## 排查过程

### 1. 先怀疑「深色对比度不够」

第一反应是把 `--border` 从 `rgba(255,255,255,0.09)` 往上调。但对照截图发现不对：**不是边框太淡，是根本没有边框**。抓 DOM 看，`border-width` 生效、`border-style: solid` 生效，说明问题在颜色。

### 2. 关键判据：写死的白色还在

截图里开关圆点是纯白、按钮文字正常，而它们所在的容器（轨道、按钮背景）是透明的。这组对比说明：

- 元素本身渲染正常
- 凡是用 `var(--xxx)` 取色的属性全部失效
- 凡是用字面量颜色的属性正常

→ 问题不在选择器、不在层叠顺序，而在**自定义属性本身的值**。

### 3. 确认变量失效而非取值为空

在 DevTools 里看 `background: var(--bg)` 那条规则，浏览器把它标成**无效（invalid at computed-value time）**——不是「取到空值」，而是「取到的值无法解析成合法颜色，整条声明作废」。

这就解释了为什么 `background` 会变成 `transparent`（初始值），而不是报错可见。

### 4. 定位到 `light-dark()`

上一轮为了消除深色变量重复，把所有颜色写成了：

```css
:root {
  color-scheme: light dark;
  --bg: light-dark(#ffffff, #1e1f23);
  --border: light-dark(rgba(0,0,0,0.08), rgba(255,255,255,0.09));
  /* ...全部 18 个变量 */
}
```

`light-dark()` 是 CSS Color 5 的标准函数（Chrome 123+）。但 **uTools 的渲染进程不支持它**，于是每个变量都变成了无法解析的值，全部声明级联作废。

### 走过的死路

- ❌ 调高 `--border` 透明度 —— 症状是「没有边框」不是「边框太淡」，改数值没用
- ❌ 怀疑 `color-scheme` 没生效 —— 它确实生效了（原生滚动条会变色），但和 `light-dark()` 是否能取值是两件事
- ❌ 怀疑 uTools 注入了样式覆盖 —— 没有；它的宿主样式挂在独立 document 上

## 根因

**uTools 的渲染进程不支持 `light-dark()`。** 使用该函数定义的自定义属性无法解析成有效颜色，凡引用它们的 `background` / `border-color` / `color` 声明全部作废，界面退化成透明。

顺带解释了「切白天没反应」：白天的变量块同样全是 `light-dark()`，所以两边一样坏。

## 修复

### 1. CSS 改回两套显式变量

```css
:root {
  color-scheme: light;
  --bg: #ffffff;
  --surface: #ffffff;
  --border: rgba(0, 0, 0, 0.1);
  /* ... */
}

:root[data-theme='dark'] {
  color-scheme: dark;
  --bg: #1e1f23;
  --surface: #2a2b31;
  --border: rgba(255, 255, 255, 0.16);
  /* ... */
}
```

代价是深色值要写一份，但这比重试一个宿主不支持的函数靠谱。

### 2. `auto` 由 JS 解析，不交给 CSS

```js
export function resolveTheme(mode) {
  const m = THEMES.includes(mode) ? mode : 'auto'
  return m === 'auto' ? (systemPrefersDark() ? 'dark' : 'light') : m
}

export function applyTheme(mode) {
  const resolved = resolveTheme(mode)
  document.documentElement.setAttribute('data-theme', resolved)
  // 监听 prefers-color-scheme 变化，但只在 auto 模式下重算
}
```

`data-theme` 永远是 `light` 或 `dark`，CSS 不需要处理第三种状态，也就不需要媒体查询兜底。

### 3. 首帧定色，避免闪白

`index.html` 里加一段内联脚本，在 React 挂载前按系统偏好先写一次 `data-theme`，之后再由保存的偏好覆盖。

### 4. 顺手修掉「深色看不见边界」

原来深色下 `--border` 只有白 9%，且按钮背景用的就是 `--bg`（与面板同色）。即使变量正常，也几乎看不出控件边界。新增并调整：

| 项 | 之前（深色） | 现在（深色） |
|---|---|---|
| `--border` | 白 9% | 白 16% |
| `--border-strong` | 白 18% | 白 32% |
| 控件背景 | `--bg`（#1e1f23） | `--surface`（#2a2b31） |
| 强调色 | #4c9aff | #5aa2ff |

`--surface` 的语义是「比当前背景亮一档的表面」：浅色下是纯白（靠边框区分），深色下是 #2a2b31（靠底色区分）。**按钮、输入框、选项卡片一律用它，不要用 `--bg`。**

## 验证

- 产物 CSS 中 `light-dark(` 出现次数 = **0**
- `:root[data-theme=dark]` 变量块完整存在，`--surface` 两个值都在
- 手动切换三档：跟随系统 / 白天 / 黑夜，每档下检查这 5 处：面板分隔线、格式卡片边框、拖放区虚线、导航选中底色、开关轨道
- 构建产物 13 个文件 / 0.27MB，不受影响

## 回归防线

1. **AGENTS.md 已写入反向警示**：`不要用 light-dark()`，并说明症状是「界面全透明」。上一轮恰恰是「新颜色写成 light-dark 一对」这条建议导致了事故，已删除并替换
2. **新增变量必须两处都加**：`:root` 与 `:root[data-theme='dark']`，漏一处就是某模式下取到上一级继承值或初始值
3. **自查问句**：改完主题相关样式，先问「如果这个变量的值不合法，界面会变成什么样」——答案是「透明」，那就必须肉眼验一遍两种模式
4. **判据沉淀**：以后遇到「某些元素样式全丢、另一些正常」，先看丢的和没丢的差别是不是「用了变量 / 用了字面量」，这比调数值快得多
